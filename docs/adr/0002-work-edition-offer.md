# 書目模型分為作品、版本、報價三層

書目模型分三層：**作品(Work) → 版本(Edition，以 ISBN 為鍵) → 報價(Offer)**。
設計原型（`design/Book Price Portal.dc.html`）把同一本書的紙本與電子書報價掛在**同一個 ISBN** 底下，
那在現實中不成立——電子書有自己的 ISBN 或根本沒有，定價也不同。
且單書比價頁的「全部版本／紙本書／電子書」切換器必須在同一頁同時呈現兩種載體的報價，
這本身就預設了「作品」這一層的存在。

## Considered Options

- **以 ISBN 扁平化成單層**：較簡單，少一張表少一次 join。但 ISBN 語意錯誤（紙本與電子書共用一個號），
  且載體切換器沒有正確的實體可以掛。
- **（採用）三層**：成本是多一個 Entity 與一次 join，換得 ISBN 語意正確與切換器有所依附。

## Consequences

第一版**不做作品的自動合併**——不去判斷哪些 ISBN 屬於同一作品，關係直接寫在 seed 資料裡。
自動合併（書名正規化、作者比對等）留作日後可加的一層，不影響現有模型。

介面上的中文字仍照設計稿寫「版本」，但**設計稿的「版本」指的是載體（紙本 vs 電子書）**，
與本 ADR 的 Edition 不是同一個概念。程式碼一律使用 Edition / Format，詳見 `CONTEXT.md`。
